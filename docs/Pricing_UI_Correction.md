Baselines: frontend `a2471e8e3d2626e3618ea497bf4f97bc1c2f9cfd`; unchanged backend `547ce1bb2f1a8b11fdd7857fae5650688356b6b0`.

## Confirmed defect and correction

Source reproduced the A-to-B retarget: previously the editor's fields survived plan selection while the update payload took the current selected ID. Awaited detail loads also had no selected-plan/request fence. The editor now records the loaded ID/name, clears only transient editor state on selection, requires the same loaded/selected ID at both button eligibility and payload construction, and separates explicit new authoring from editing. Details publish only for the latest live selection/request/context; stale results and errors, competing loads, wrong detail IDs, unmount and context replacement cannot populate the editor. Exact loaded and selected target name/ID appear before update/delete. Current history must identify the same unpublished plan; backend immutability remains authoritative.

No persisted intent is cleared or retargeted by editor selection. The unchanged adapter still stores original context/API origin/operation ID/content before sending. Drafts lack durable server receipts, so uncertain draft writes remain non-replayable and non-abandonable through this UI. Confirmed receipt-backed operations retain explicit original retries independent of new form completeness.

## Structured authoring and compatibility

Required JSON textareas are replaced with labelled add/edit/remove rows for zone/weight rates, every supported transit field, country-qualified routes, included service codes, exact fees and discounts. Eligible invoice states use explicit checkboxes. Optional fields remain optional; countries normalize uppercase, route/codes trim, zone zero is retained. No country/zone remapping, price, fee, percentage, currency or tax defaults are introduced. Explicit None buttons represent supported empty rate/transit/fee/discount collections; required route/service/state arrays still reject empty input. Row maxima remain rates 1000, transit 50, routes 100, included services/fees 30 and discounts 10; existing scalar/row schemas validate bounds. The server still validates cross-row/strategy and approval rules.

Fee/discount/tax money remains exact decimal text, including long fractions. Percentage comparison is exact, without floating-point financial calculation. Tariff draft rates retain the existing numeric API contract: textual controls convert only during normalization, and accepted pricing remains server-derived. All existing scalar tariff/policy fields are retained. The policy displays a business-readable summary plus read-only exact JSON evidence; JSON is not an authoring requirement. Incomplete/invalid new policies cannot submit. Existing pending intents cannot be overwritten by edited form values or refreshed selectors.

Changed implementation: `PricingConfigurationWorkspace.tsx`, `BillingPolicyForm.tsx`, new `PricingRows.tsx` and `lib/pricing-editor.ts`. New test: `tests/pricing-editor.test.cjs`. No API, backend source, schema, permission, dependency or deployment changes. Initial linear/transit publication, reference mutation and receipt-less draft reconciliation limitations remain as recorded in Pricing_Billing_UI.md.
